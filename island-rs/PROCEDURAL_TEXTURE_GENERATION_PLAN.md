# Engine-Neutral Procedural Texture Generation

## Objective

Build a deterministic procedural texture baker in Rust that replaces the
legacy imported terrain-texture assets formerly used by the Unity terrain.
The same Rust library must be usable in process by other renderers, while a
standalone command-line tool must be able to produce ordinary image files for
engines that do not call Rust directly.

The first visual target is an independently generated cracked-stone surface
with the same useful characteristics as the current rock treatment: large
irregular slabs, narrow branching cracks, rounded crack shoulders, quiet
surface variation and readable relief. A second rounded-stone preset is needed
for the riverbed so the imported texture dependency can be removed.

Every material will be generated from one authoritative periodic height field.
Normal and occlusion maps will be derived from that height field rather than
invented independently, so a crack cannot be high in one map, flat in another
and bright in the occlusion map.

## Current state and dependency boundary

The Unity terrain material now uses the generated material sets:

- `_RockAlbedoMap`, `_RockNormalMap`, and `_RockMaskMap` use the generated
  cracked-stone colour, normal, height, and occlusion outputs.
- `_RiverBedAlbedoMap`, `_RiverBedNormalMap`, and `_RiverBedMaskMap` use the
  generated rounded-river-stone outputs.
- Both material occlusion channels are enabled and deliberately tuned.

The Unity shader contract is already suitable for generated textures:

- albedo is sampled as colour data;
- tangent-space normals are sampled through Unity's normal-map importer;
- packed material mask `R` is height;
- packed material mask `G` is occlusion;
- packed material mask `B` is currently unused;
- packed material mask `A` is one.

The newly added `island-bevy` crate is already a second in-process consumer of
`island-rs`. It currently evaluates its detail noise in WGSL and intentionally
loads no texture assets. This work must not force that renderer to adopt baked
textures, but it provides a concrete proof that the Rust API must remain free
of Unity types and file-layout assumptions.

## Decisions

### Rust owns generation

`island-rs` will own:

- recipe validation and versioning;
- deterministic random hashing;
- periodic noise and cellular fields;
- height and material construction;
- normal derivation;
- local ambient-occlusion derivation;
- colour construction;
- channel packing;
- image encoding;
- the command-line baker.

Unity will only invoke the baker, import the results, configure import settings
and assign textures to a material. Other engines may either call the Rust API
or consume the same generated files.

### Use a height field, not a dense source mesh

A dense displaced mesh would eventually be rasterized back into a height field
to make the requested maps. It adds topology, UV, projection and rasterization
problems without adding information that a height map can retain. In
particular, overhangs still cannot survive the bake.

The production baker will therefore operate directly on a periodic 2D field.
A tessellated plane may be generated by an engine adapter for displacement
preview, but it is a view of the height field and not an input to the bake.

### Keep the core engine-neutral

The public API will expose typed images and an owned texture set. It will not
expose Unity `Texture2D`, Bevy `Image`, shader property names or asset paths.
Engine-specific packing and import behavior live at the output or adapter
boundary.

### Prefer enums over a dynamic node graph

The first implementation will use enums for noise kinds, blend operations,
normal conventions, material models and output profiles. It will not use boxed
trait objects or build a general visual node graph. A recipe enum is matched
once when a whole field pass begins rather than dynamically dispatched for
every pixel.

This keeps recipe deserialization exhaustive and the selected algorithm
visible. If later recipes genuinely require arbitrary graphs, a compiled field
program can be added without changing the image and texture-set contracts.

### Generate offline first

The initial supported workflows are the Rust library and CLI. Runtime FFI
generation is optional later work. Offline generation makes it possible to
commit stable textures, avoids startup work in games and avoids coupling asset
creation to a loaded Unity native plugin.

The existing terrain-specific `src/noise.rs` can share its integer mixing

current non-periodic sampling contract should not be silently changed because
that could alter generated islands for every existing seed.

## Public Rust boundary

The exact names may change during implementation, but the ownership and data
flow should follow this shape:

```rust
pub fn generate_texture_set(
    recipe: &TextureRecipe,
    normal_convention: NormalConvention,
) -> Result<TextureSet, TextureError>;

pub fn write_texture_set(
    textures: &TextureSet,
    destination: &Path,
    options: &OutputOptions,
) -> Result<OutputManifest, TextureError>;
```

The recipe and output options are borrowed because generation does not retain
them. `TextureSet` owns its finished buffers because engine callers may keep,
upload or encode them after the recipe goes out of scope.

Suggested result types:

```rust
pub struct TextureSet {
    pub dimensions: TextureDimensions,
    pub albedo: Rgb8Image,
    pub height: Gray16Image,
    pub normal: Rgb8Image,
    pub occlusion: Gray8Image,
    pub metadata: TextureMetadata,
}

pub struct Image<T> {
    width: u32,
    height: u32,
    pixels: Vec<T>,
}
```

The concrete aliases can use `[u8; 3]`, `[u8; 4]`, `u8` and `u16` pixels. Each
image constructor must validate `width * height == pixels.len()` with checked
arithmetic. Public accessors should return slices rather than cloning buffers.
Packed engine profiles are produced on request from `&TextureSet`; they are not
retained in the core result and do not duplicate image-sized buffers unless a
caller actually asks for them.

One private `BakeWorkspace` will own reusable floating-point and cellular
scratch arrays. Passes will borrow and overwrite those arrays in phases rather
than retaining every intermediate noise layer. At 2048 by 2048, one `f32`
field is approximately 16 MiB, so avoiding unnecessary simultaneous fields is
material to editor usability.

## Recipe format

Recipes will be UTF-8 JSON using `serde` and `serde_json`. JSON is not the most
compact format, but it is easy to generate and inspect from Unity, Bevy, Godot,
Unreal build tools and ordinary scripts.

Every recipe must contain one unambiguous current document shape:

- human-readable `name`;
- `seed`;
- width and height;
- physical tile width and height in metres;
- a material model and its parameters;
- an ordered `layers` stack with stable IDs, scalar sources, remapping and
  independent height/albedo output bindings;
- normal and displacement scale;
- occlusion settings;
- albedo palette and variation settings;
- requested output profiles.

The schema will use tagged enums so unknown kinds and misspelled variants fail
with a useful path instead of silently falling back. The root material model
will initially be one of:

- `layered_noise` for general height-field experimentation;
- `cracked_stone` for irregular connected slabs;
- `rounded_stones` for smaller separated river stones.

Noise types available to recipes will initially be:

- interpolated value noise;
- fractal Brownian motion;
- billow noise;
- ridged noise;
- cellular distance to the nearest feature;
- cellular distance to an edge;
- per-cell random values;
- domain-warped variants of the preceding fields.

Height layer blend operations will be:

- replace;
- add and subtract;
- multiply;
- minimum and maximum;
- lerp by a fixed amount or a generated mask.

Albedo layer bindings use `replace`, `mix`, `multiply`, `add` or `overlay`,
with an independent unitless strength and a two-colour ramp or multi-stop
linear-RGB gradient.

Each scalar source can specify frequency, octaves, lacunarity, gain, offset,
seed domain, cellular settings and an optional explicit domain warp. A layer's
remap is applied once before its value is routed to height and/or albedo;
height strength is expressed in metres and albedo strength is unitless.
Frequencies must be meaningful in tile space rather than accidentally
depending on output resolution. A mask may reference only an earlier layer by
stable ID.

Recipe validation must reject:

- zero dimensions;
- dimensions whose pixel counts overflow `usize`;
- non-finite numeric values;
- negative physical tile sizes;
- zero cellular frequency;
- unknown or malformed current-format fields;
- octave counts over a documented safety limit;
- AO sample counts or radii outside safe limits;
- output paths or names that would collide within one texture set.

## Exact tiling rules

Tileability must be inherent to every source field. Cropping a larger
non-periodic image or blending opposite edges after generation is not
acceptable because both approaches leave derivative and mipmap discontinuities.

The baker will:

- wrap integer lattice coordinates by the layer's lattice period before
  hashing;
- treat cellular neighbours across each border as periodic copies;
- build domain-warp fields with the same period as the field they warp;
- sample pixel centres at `(x + 0.5) / width` and `(y + 0.5) / height`;
- wrap all finite-difference, blur and horizon lookups;
- never duplicate the first pixel as the final pixel;
- derive normal and AO maps before quantization.

The periodic sampler should accept a seed-domain value so two layers can share
a seed without sharing the same lattice. Integer hashing must be used for the
random basis; engine-specific Perlin implementations are not deterministic
enough for a portable recipe.

Row-parallel work with Rayon is allowed because each output pixel is
independent. Reductions within a pixel must retain a fixed iteration order so
thread scheduling cannot change output bytes.

## Cracked-stone construction

The cracked-stone preset will be purpose-built from the shared field
primitives rather than relying on one noise layer to resemble cracks by chance.

### 1. Periodic slab layout

Generate a coarse periodic cellular field with jittered feature points. For
each pixel retain:

- nearest cell identifier;
- distance to the nearest feature point;
- distance to the second-nearest feature point;
- an approximation of distance to the nearest cell boundary.

The feature grid must be evaluated with wrapped neighbouring cells so slabs
crossing an image boundary continue on the opposite side.

### 2. Broad domain warp

Warp the cellular query point with two low-frequency periodic noise fields.
Warp amplitude must remain small relative to the feature-cell size; excessive
warp stretches cracks into long parallel filaments and makes the result look
combed.

### 3. Crack channel

Use the difference between the nearest and second-nearest cellular distances
to identify slab boundaries. Modulate the threshold with broad and medium
noise to vary crack width without breaking continuity.

The crack floor should have a configurable base depth. It should not be pure
black in the stored height map unless the recipe explicitly requests the full
available displacement range.

### 4. Rounded shoulders

Remap distance from each crack through a smooth bevel curve. The desired
profile is:

- a narrow low crack floor;
- a steep but rounded inner wall;
- a broader shoulder returning to the slab surface;
- a quiet centre that is not inflated into a pillow.

This height profile, rather than a painted outline, is what gives the normal
and occlusion maps their matching crack edges.

### 5. Slab-scale variation

Use the stable cell identifier to assign each slab a small independent height
and colour bias. Add a subtle per-cell plane or broad convex profile so
adjacent slabs do not all sit at the same height.

The bias range must stay well below crack depth. Otherwise neighbouring slabs
will read as overlapping roof tiles rather than one cracked surface.

### 6. Secondary fractures

Add a sparse field of short internal fractures, masked by cell interiors and
seeded per cell. These should taper to dead ends and occur in only some slabs.
They must join the main crack channel cleanly when they reach an edge.

This is a separate feature from high-frequency surface noise. Using ordinary
fBM for both creates dark stripes rather than recognizable fractures.

### 7. Surface detail

Layer broad cloudy variation, shallow pits and fine grain over the completed
slab field. Surface detail is attenuated inside the crack floor and may be
slightly stronger on shoulders. Its amplitude must not invert the large-scale
height ordering.

## Rounded river-stone construction

The riverbed preset shares the same infrastructure but needs a different
material model:

- more numerous and smaller cellular features;
- a rounded radial profile around each cell centre;
- deliberate gaps between stones rather than connected slab boundaries;
- larger per-cell height and colour variation;
- optional elongated stones from an anisotropic cell metric;
- fine sand or silt noise in the gaps;
- stronger short-range occlusion between neighbouring stones.

The first migration can use a fixed two-metre physical tile to match the
current `_RiverBedTextureWorldSize`. The cracked-stone recipe should initially
use a four-metre tile to match `_RockTextureWorldSize`.

## Height representation

The internal height field uses linear `f32` metres relative to the material's
local surface plane. Recipes state a physical relief range, rather than an
arbitrary normal strength, so normal and AO generation can account for the
same horizontal and vertical scale.

The standalone height image will use unsigned 16-bit grayscale PNG. Metadata
will record:

- minimum represented height in metres;
- maximum represented height in metres;
- neutral/base height;
- physical tile dimensions;
- whether a consumer should interpret the map as displacement or only as a
  blend-height signal.

The Unity mask uses an 8-bit quantized copy because the current shader samples
height only to perturb a material transition. The 16-bit source remains
available for other engines and for future tessellation or parallax work.

## Normal-map generation

Normals will be derived from the unquantized height field using wrapped central
differences. Pixel spacing is calculated from the recipe's physical tile size,
so changing texture resolution alone does not change perceived relief.

The unencoded tangent-space normal is:

```text
normalize(-dheight/dx, -dheight/dy, 1)
```

The output convention controls the encoded green channel:

- `open_gl`: positive tangent Y is encoded directly;
- `direct_x`: tangent Y is inverted.

The manifest records the convention. Unity's generated recipe will use the
convention verified against the existing `UnpackNormal` and top-down tangent
remapping in `TerrainDetail.shader`; no assumption should be finalized without
the rendered slope test.

Normals are encoded as RGB8. The source PNG remains an ordinary portable normal
map; Unity import-time channel swizzling or compression is Unity's concern.

## Occlusion-map generation

Occlusion is a material-local relief approximation, distinct from the
island-wide terrain/canopy occlusion map. Its public convention is:

- `1.0` or byte `255`: fully open and unoccluded;
- `0.0` or byte `0`: fully occluded.

It combines two terms derived from the unquantized height:

### Cavity term

Compare each pixel with wrapped, progressively wider local averages. Pixels
below their neighbourhood darken; exposed peaks remain open. This cheaply
captures narrow cracks and spaces between river stones.

### Horizon term

For a fixed set of directions, sample wrapped heights at exponentially
increasing radii and retain the largest positive horizon slope. Convert the
mean directional horizon to an occlusion factor using configurable strength
and power.

The initial quality preset should use eight directions and six or eight radii.
The recipe may expose a lower preview quality, but output must be deterministic
for a given quality setting. AO loops should operate on rows in parallel and
reuse one output buffer; they must not allocate per pixel.

The cavity and horizon terms are combined multiplicatively or by a configurable
weighted minimum. The default cracked-stone recipe should leave slab centres
near white while clearly darkening crack floors and the lower side of large
height steps.

## Albedo generation

Albedo is constructed in linear colour and converted to sRGB only while
encoding the albedo PNG. It must not contain a fixed directional light or
specular highlight, because engine lighting supplies those at runtime.

The cracked-stone albedo combines:

- a configurable cool/warm base palette;
- low-amplitude per-cell colour variation;
- broad and medium cloudy noise;
- modest darkening in deep crack floors;
- subtle shoulder variation;
- sparse mineral flecks or stains;
- optional AO influence limited so indirect lighting is not baked twice.

The visual target may be inspected while tuning, but generated outputs must not
sample, transform or redistribute pixels from the imported asset pack.

## Output profiles and files

The default `separate` profile writes:

```text
<name>_albedo.png       RGB8, sRGB
<name>_height.png       Gray16, linear
<name>_normal.png       RGB8, linear normal data
<name>_occlusion.png    Gray8, linear
<name>.texture-set.json metadata and hashes
```

The `motu_unity_terrain` profile additionally writes:

```text
<name>_mask.png         RGBA8: R height, G occlusion, B 0, A 255
```

Packing is downstream from map generation. Adding a common ORM output for
another engine must not require changing the material model or AO algorithm.

The manifest records:

- recipe schema and generator algorithm versions;
- recipe seed and a hash of normalized recipe content;
- dimensions and physical size;
- map filenames, formats and colour spaces;
- normal convention;
- height scale and bias;
- packed channel meanings;
- a content hash for every output.

Use the `png` crate for standards-compliant 8-bit and 16-bit output rather than
growing the existing minimal RGB8 PNG writer into a second general-purpose
codec. Keep image encoding behind `encoding.rs` so in-process engine consumers
do not need to encode files.

## Command-line interface

Add an `island-texture-baker` binary with this initial interface:

```text
island-texture-baker \
  --recipe island-rs/texture-recipes/cracked-stone.json \
  --output island-unity/Assets/Generated/Textures/CrackedStone \
  --normal-convention direct-x
```

Required behavior:

- validate the full recipe before creating output files;
- require the calling engine or tool to select the normal convention;
- create the destination directory when its parent exists;
- write each image to a temporary sibling and rename it into place;
- write the manifest last so its presence means the set completed;
- refuse to replace unrelated files;
- require `--force` before replacing an existing generated set;
- print the seed, dimensions, elapsed time and output hashes;
- return a non-zero exit code on invalid input or partial output failure;
- provide `--help` and `--version` without starting a bake.

Useful follow-up options are `--seed`, `--width`, `--height` and `--profile` as
explicit recipe overrides. Overrides must be reported in the manifest so the
output remains reproducible.

## Unity adapter

After the Rust CLI and the cracked-stone output are stable, extend the existing
terrain mask editor or add a focused `ProceduralTextureBakerWindow` under
`island-unity/Assets/Editor`.

The Unity code will:

1. Select a committed recipe.
2. Select an output directory under `Assets/Generated/Textures`.
3. Invoke a configured release baker executable, with a documented Cargo
   fallback for development machines.
4. Capture stdout, stderr and exit status.
5. Refresh the Asset Database only after a successful process.
6. Configure albedo as sRGB with repeat wrapping and mipmaps.
7. Configure height, occlusion and packed masks as linear data.
8. Configure the normal output as `TextureImporterType.NormalMap`.
9. Optionally assign a completed texture set to `IslandTerrain.mat` with Undo.
10. Retain the current textures if generation, import or validation fails.

The adapter may display a tessellated plane and tiled 3-by-3 preview. It must
not contain a second implementation of any noise, normal or AO formula.

Generated `.png` and `.meta` files intended for the shipped Unity project
should be committed. Recipe files are the authoritative source, but committing
outputs lets collaborators open Unity without first installing the Rust tool.

## Bevy and other engines

No initial Bevy rendering change is required. Its current world-space WGSL
noise is useful and should remain asset-free unless there is a separate visual
reason to adopt the generated maps.

Portability is demonstrated by two independent interfaces:

- `island-rs` callers can receive `TextureSet` buffers directly and create an
  engine-native GPU image without PNG encoding;
- any engine or content pipeline can execute `island-texture-baker` and load
  its standard PNG files and manifest.

A later Bevy validation example may convert the owned buffers to Bevy `Image`
objects behind an opt-in material or example binary. That adapter must live in
`island-bevy`, not in the generator library, so `island-rs` never depends on
Bevy.

An FFI texture-set export may be added later if Unity needs in-process runtime
generation. It should mirror the existing owned-handle/release pattern used by
surface maps and expose separate buffers plus dimensions. It is not required
for dependency removal.

## Performance and memory plan

The baker is offline but must still be comfortable at 2048 by 2048:

- evaluate independent rows with Rayon;
- compute cellular candidates from a bounded neighbouring-cell stencil rather
  than comparing every pixel with every feature point;
- keep integer hashes stateless;
- reuse `BakeWorkspace` arrays between passes;
- keep only attributes needed by later passes;
- avoid allocating inside pixel loops;
- use exponentially spaced AO radii to cover broad relief with few samples;
- encode images after large floating-point scratch fields can be released;
- report peak working dimensions and stage timings in profiling builds.

The first benchmark target is a full 2048-square cracked-stone set at release
optimization. The plan does not impose a speculative time limit, but generation
must be measured before the Unity UI is considered complete. If horizon AO is
dominant, optimize its sampling or quality presets before weakening its visual
contract.

## Determinism contract

For the same generator algorithm version, recipe bytes after normalization and
supported target, repeated runs must produce identical output bytes regardless
of Rayon scheduling.

Do not promise cross-architecture byte identity until it has been verified on
the required platforms. Floating-point contraction and library behavior can
differ between targets. The manifest's algorithm version allows a deliberate
change to retire old golden hashes rather than pretending the output did not
change.

Algorithm changes that intentionally alter output must:

- increment the texture algorithm version;
- update fixed-seed golden statistics or hashes;
- regenerate committed texture sets;
- describe the visual reason in the commit.

## Validation strategy

### Unit tests

- Integer hashing is stable for known inputs.
- Every noise primitive repeats at its declared period.
- Cellular identifiers and edge distances continue across both axes.
- Domain warping remains periodic.
- Field blending and remapping obey documented ranges.
- Recipe validation rejects invalid dimensions, non-finite values and unsafe
  sample counts.
- Wrapped central differences give a flat normal for a constant field and the
  expected direction for a known periodic wave.
- Normal encoders differ only in the green channel between OpenGL and DirectX
  conventions.
- Flat height produces white occlusion.
- A synthetic trench darkens in its floor and stays open on its plateau.
- Image constructors reject mismatched dimensions and buffer lengths.
- Unity packing writes height to red, occlusion to green, zero to blue and one
  to alpha.

### Integration tests

- A small fixed recipe generates byte-identical outputs twice.
- Different seeds alter every intended stochastic field.
- The CLI writes all requested files and writes the manifest last.
- Invalid recipes produce no completed manifest.
- `--force` is required to replace an existing set.
- Encoded PNG dimensions, bit depths and colour types match their contracts.
- Manifest hashes match the files on disk.

### Seam tests

- Evaluate source fields at `p`, `p + period_x` and `p + period_y` within a
  documented floating-point tolerance.
- Compare wrapped derivatives on both sides of each boundary.
- Tile height, normal, AO and albedo outputs 3-by-3 and inspect all joins.
- Verify generated mipmaps in Unity do not expose border discontinuities.

### Statistical tests

For fixed test recipes, assert broad properties rather than only a brittle
whole-image hash:

- crack coverage falls inside a target range;
- slab-count and slab-area distributions remain plausible;
- height uses an expected portion of its range;
- normal vectors decode to approximately unit length;
- occlusion is mostly open but has a meaningful dark tail;
- crack pixels are darker in AO than slab centres;
- albedo luminance and saturation stay in the configured range.

### Visual validation

- Save a labelled contact sheet of albedo, height, normal, AO and packed mask.
- Inspect a 3-by-3 tiled flat preview.
- Inspect a tessellated displaced preview under a rotating directional light.
- Compare generated rock with the previous material on level terrain, the
  slope-transition band and steep cliffs.
- Inspect at the current four-metre rock and two-metre riverbed world sizes.
- Check close, gameplay and distant views for aliasing and obvious repetition.
- Confirm AO remains subtle under direct light and readable under ambient light.
- Compile the Unity shader and run the existing batch validation path.
- Optionally render a Bevy material example using the in-memory buffers as an
  independent coordinate and normal-convention check.

### Rust quality gates

Run at minimum:

```text
cargo fmt --all --manifest-path island-rs/Cargo.toml -- --check
cargo test --manifest-path island-rs/Cargo.toml --all-targets
cargo clippy --manifest-path island-rs/Cargo.toml \
  --all-targets --all-features -- -D warnings
```

Focused texture tests should run first during iteration. Full existing island
tests remain a release gate because refactoring deterministic hashing or PNG
support must not change unrelated terrain generation.

## Migration phases

### Phase 1: Contracts and periodic field core

- Add typed image, dimension, error and texture-set types.
- Add recipe structs, tagged enums and validation.
- Extract or share deterministic hashing without changing existing island
  noise output.
- Implement periodic value, fBM, billow, ridged and domain-warp sampling.
- Implement periodic cellular sampling and tests.

Exit gate: all source fields are deterministic and pass boundary-period tests.

### Phase 2: Authoritative height and derived maps

- Implement layered field evaluation with reusable scratch storage.
- Implement wrapped normal derivation using physical units.
- Implement cavity and horizon occlusion.
- Add image quantization and packing.
- Add synthetic normal and AO tests.

Exit gate: one synthetic height field produces mutually consistent height,
normal and occlusion maps with no seams.

### Phase 3: Cracked-stone material

- Implement the specialized cracked-stone model.
- Add slab, crack, bevel, secondary-fracture and surface-detail controls.
- Implement lighting-free stylized albedo.
- Create `cracked-stone.json` at a four-metre physical period.
- Tune at a smaller preview size before the 2048-square final bake.

Exit gate: the generated set meets the statistical tests and passes flat,
displaced and Unity terrain visual review.

### Phase 4: Encoding and CLI

- Add standards-compliant PNG encoding.
- Add separate and Unity mask output profiles.
- Add manifest generation and content hashes.
- Add atomic output behavior and `--force` protection.
- Add CLI integration tests and documentation.

Exit gate: a machine with Rust but no game engine can generate and validate the
complete texture set from a committed recipe.

### Phase 5: Unity integration and rock migration

- Add the thin Editor invocation/import window.
- Generate assets under `Assets/Generated/Textures/CrackedStone`.
- Assign generated rock albedo, normal and mask textures.
- Tune normal, height-blend and occlusion strengths.
- Preserve the old material references until visual acceptance.

Exit gate: Unity uses only generated rock textures and retains correct shadows,
lighting, slope blending and mipmapped tiling.

### Phase 6: Rounded river stones

- Implement and tune the rounded-stone model.
- Generate a two-metre riverbed texture set.
- Migrate riverbed albedo, normal and mask references.
- Validate the result below water as well as on exposed banks.

Exit gate: neither rock nor riverbed materials reference imported pack assets.

### Phase 7: Remove the dependency

- Search all scenes, prefabs, materials, scripts and metadata for the imported
  legacy imported asset GUIDs and paths.
- Confirm every replacement texture and `.meta` file is committed.
- Remove the imported texture directory and its root `.meta` file.
- Remove or update only the third-party notice entries that apply exclusively
  to that package.
- Open the project from a clean checkout and verify no missing references.
- Run Rust, Unity shader and batch validation gates again.

Exit gate: a clean clone builds and renders without the Asset Store package.

### Phase 8: Optional engine adapters

- Add an opt-in Bevy example that uploads `TextureSet` buffers directly.
- Document Godot and Unreal import conventions from the manifest.
- Add common packed profiles only when a real consumer requires them.
- Consider extracting the module into its own crate if another repository needs
  it independently of the island generator.

This phase is not required to remove the Unity dependency; the public Rust API
and CLI already provide the engine-neutral boundary.

## Risks and mitigations

### A generic system delays the first useful texture

Mitigation: implement shared periodic primitives and a specialized
`cracked_stone` model before considering arbitrary field graphs or an editor
node UI.

### Seams appear only in derived maps

Mitigation: make wrapping a property of the image sampler used by gradients,
blur and AO, and test every output separately rather than testing source noise
alone.

### AO becomes the dominant bake cost

Mitigation: use fixed directions, exponentially spaced radii, Rayon row
parallelism and preview/final quality presets. Measure before changing the
visual algorithm.

### Height, normal and shader scale disagree

Mitigation: store tile dimensions and relief in physical metres and derive
normal slopes from those values. Record the same data in the manifest.

### Normal maps look inverted in one engine

Mitigation: encode an explicit convention, record it in the manifest and keep
green-channel inversion at the output boundary rather than inside height
derivation.

### Colour-space mistakes flatten or over-contrast maps

Mitigation: record colour space per output and make Unity import settings part
of automated editor validation. Only albedo is sRGB; height, normal, AO and
packed masks are data.

### Generated output is visually too regular

Mitigation: combine periodic cellular structure with low-amplitude domain warp,
per-cell variation, secondary fractures and multiple non-harmonic surface
scales. Do not solve repetition by increasing warp until it produces stripes.

### Removing the pack breaks hidden references

Mitigation: migrate rock and riverbed separately, retain the old folder until
both are accepted, audit GUIDs immediately before deletion and verify from a
clean checkout afterward.

## Definition of done

- `island-rs` exposes an engine-neutral, documented texture-generation API.
- A standalone Rust CLI generates textures from the current JSON recipes.
- Cracked-stone and rounded-river-stone recipes are committed.
- Albedo, 16-bit height, normal, occlusion and Unity-packed mask outputs are
  deterministic and seamless.
- Normal and occlusion maps are derived from the same unquantized height field.
- Unity imports and assigns the outputs through a thin Editor-only adapter.
- Generated rock AO is deliberately enabled and visually tuned rather than
  merely written to an unused channel.
- Rust formatting, tests and strict Clippy pass.
- Unity shader compilation and batch validation pass.
- A clean checkout contains no unresolved legacy texture GUIDs or paths.
- The legacy imported texture package can be removed without changing terrain
  or riverbed material functionality.
